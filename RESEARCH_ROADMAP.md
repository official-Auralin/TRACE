# TRACE completion and study gates

## Current milestones

**Milestone one — public lab demo.** Publish the validated framework, then deploy only the curated Pages artifact. `trace.demo.v1` adds exact local feedback, immutable first submissions within the session record, explicit retries/reveals, browser-local resume, continued access to the finite public pool, structural band selection and a shared local agent transport. Source, browser behavior and cross-language grading require actual checks. Local progress is editable and is not a research export. The existing server study remains `trace-study-v5`.

**Milestone two — collection and learning-enabled comparison.** Host the shared Python service with durable storage and a new exposure-aware protocol; record first submission before feedback, assistance and repeated exposure separately. Define public free-play analysis versus fixed common challenge sequences. Extend agent history/feedback handling under declared budgets, and validate the revised analysis before comparing populations. Complete institutional records, comprehension/accessibility pilot, registration and actual collection as below. Published v5 tasks are public benchmark material; reserve a new pool for any concealed-item claim.

The gates below describe the preserved v5 fixed-form study where their settings differ. Receipt-only scores and isolated agent contexts are not the defaults of the new public demo and must not be silently carried into the future learning-enabled comparison. The demo's structural bands remain uncalibrated until actual evidence exists. A public lab release does not itself complete the empirical gates.

## Implemented research scope

The primary task is finite event explanation: one inclusion-minimal input-cell set meeting both guarantee and prevention. The underlying method is a bounded two-player verification game solved backward. General policy-changing reverse parity, arbitrary LTL compilation, and infinite liveness experiments are separate extensions, not claims of this release.

## Gate A — semantic and executable closure

Required evidence: exact ALGORITHM_SPEC; general executable Lean constructor/output/explanation correspondence; recurrence/minimality/search and checked-query binding proofs without admissions; all-state/input local source-to-level agreement; one checked canonical-answer or absence certificate per item; independent exhaustive small-fixture word/candidate checks; forged-record rejection; deterministic package reproduction; current source-bound manifest. The source-to-proof-to-grader trust ledger remains explicit. All-answer enumeration is optional bounded audit evidence, not a scalable release prerequisite.

Archive superseded records. Preserve the separately archived original repository, Summer26 sources, and archive/v2-textbook. Do not pool old union scores or rejected-interface playtests with v5 visual outcomes.

## Gate B — instrument and analysis closure

Required evidence: common human/agent instructions and public observations, browser and endpoint tests, accepted alternative answers, receipt-only scored feedback, deadline/probe/first-submission enforcement, durable withdrawal and request records, configuration/run provenance, analysis rejection of incompatible inputs, and uncertainty procedures whose assumptions and limitations are explicit.

Synthetic checks establish software behavior; they do not establish human comprehension or language-model compatibility with a real provider.

## Gate C — institutional record and pilot

The investigator must supply the applicable institutional determination, participant contacts, compensation, retention and withdrawal choices. These cannot be inferred or fabricated by the implementation.

After that record is complete, run 6–10 consenting adults on pilot items. Test comprehension, interface usability, accessibility, time burden, and technical integrity. Record revisions. If task wording, timing or representation changes, revise both human and agent protocols and repeat the affected pilot checks.

## Gate D — registration and freeze

Freeze dataset, code/protocol hashes, forms, prompts, model snapshots, conditions, primary contrast, sample/stopping rules, missingness rules and analysis before main outcomes are examined. A local template is not preregistration.

The shared human–agent panel is 64 items; the full agent benchmark is 1,024. Eight independent judgments per panel item implies 128 usable humans per condition, a coverage target rather than demonstrated power. Decide the final sample using pilot-informed precision planning and realistic resources.

## Gate E — actual collection

Collect the human sessions and isolated model repetitions under matched information and probe budgets. Keep provider/configuration identities and independent run cohorts intact. Record failures and withdrawals without performance-based exclusions. Repository-aware coding agents are not valid benchmark participants.

Paid model calls and participant recruitment are separate research operations requiring the actual configured accounts and completed participant record. No such observations are created by a software verification command.

## Gate F — analysis and manuscript

Analyze immutable versioned logs using the registered plan. Compare populations only on matched items and conditions. Report guarantee failures, prevention failures, valid-but-nonminimal answers, malformed responses and timeouts separately. Do not infer internal reasoning from answer shape alone.

Populate TRIAL-PILOT, TRIAL-SAMPLE, TRIAL-PRIMARY, TRIAL-SECONDARY, TRIAL-MODALITY, TRIAL-ERRORS, TRIAL-LIMITATIONS, TRIAL-CONCLUSION, and the abstract result slot from actual evidence. Optional unperformed analyses must be declared unperformed. Human ease and an AI reasoning gap are hypotheses until measured.

## Full strategy extension gate

A future N2 experiment must supply the original or explicitly constructed plant arena, owners, legal alternatives, initial position, baseline memory, editable system positions, candidate grammar, background/effect monitors and acceptance convention. Certify baseline actuality, removal feasibility, the exact winning region, accepted preserving witnesses and exclusion certificates. Instantiate the existing same-strategy fallback theorem. Infinite behavior requires an accepted lasso/strategy certificate; a finite animation or favorable SCC minimum is insufficient.

This extension cannot be advertised as implemented by merely embedding finite terminal outcomes in parity sinks.

## Visual acceptance before main collection

Every source machine/trace/target is compiled to a visible switch-and-light task, with original input cells, linked copies, all counterfactual transitions and nonlatching round outputs preserved. Technical acceptance requires the general Lean correspondence, proved output-only terminal projection, concrete transition checks, one common visual target and a distinct dark exit for every terminal route, shared teaching/actions, accessible controls and navigable rendering. Post-target state distinctions must not introduce apparent additional goals. Earlier-state distinctions remain intact. Small boards must be understandable without the technical drawer; large boards may exceed human ability. These checks do not establish comprehension or enjoyment.

The pilot must assess whether participants understand the two explanation tests after visual examples, identify the single target even when it is off, distinguish earlier status indicators from the goal, interpret linked controls, and predict unseen routes without simulator queries. Record crossings, navigation burden, help requests and device limitations. Revisions require a new protocol/data/source version and affected revalidation before main collection. Parameter strata are provisional sampling labels; validate actual difficulty rather than assuming larger machines are harder. Semantic duplicate/group analysis is required before making mechanism-held-out generalization claims.
